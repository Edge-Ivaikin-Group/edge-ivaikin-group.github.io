# Hunt ladder funnel pages (edgeivaikin.com)

Separate pages for the funnel, next to the existing site. Existing pages, their text and design are not changed.
EN: `/ladder/N/`, RU: `/ru/ladder/N/`, N = 1..7. `noindex`, not in `sitemap.xml`, not in `robots.txt`, not linked from any existing page.
Generated by `node scripts/build-funnel.mjs` (output committed); copy only from text already published on this site (home pages, cases, pricing, FAQ). ZH and AR are not built.
Styles: `styles.css` + `landing.css` + `funnel.css` (funnel-only additions). Scripts: `goals.js` and `ladder-funnel.js`. The existing-page `ladder.js` is NOT loaded here.

| Step | Hunt level | Own stage event |
| :-- | :-- | :-- |
| 1 | unaware, entry | `ladder_1_landing` (first funnel page of the visit, any step; `funnel_step` shows where) |
| 2 | problem-aware | `ladder_2_problem` (page block seen 0.5 s) |
| 3 | solution-aware | `ladder_3_solution` |
| 4 | product-aware, proof | `ladder_4_proof` |
| 5 | most aware, offer | `ladder_5_offer` |
| 6 | intent | `ladder_6_intent` (page seen 0.5 s, `trigger=step_page`) |
| 7 | conversion, contact | `ladder_7_conversion` (direct contact click: calendar, Telegram, bot, email, phone), `ladder_aux_contact_view` |

Each page links to the next step and to step 7 (`data-ladder-contact`, counts as intent, `trigger=contact_step`) and has a plain Telegram link. Helpers: `ladder_aux_scroll_50`, `ladder_aux_scroll_90`, `ladder_aux_time_30s`. `goals.js` sends the `cta_*` goals as before; on these pages `window.edgeFunnelEntry = "funnel_page"` adds the parameter `entry = funnel_page` to them.

## Parameters

All funnel-page events: `entry = funnel_page`, `funnel_step` (1..7), `lang`, `ab_hero = none`, `page`. `ladder_1_landing` also `source` (coarse category: direct, search, social, messenger, referral, internal, campaign, paid) and `landing`. Others: `section`, `trigger`, `channel` as on the home pages.
In Metrika: goals ladder_* already exist as JavaScript events; filter the goal report by the parameter `entry = funnel_page`.

## A/B rule

- Metric: `ladder_7_conversion` rate per funnel-page visitor = visitors with `ladder_7_conversion` and `entry=funnel_page` / visitors with `ladder_1_landing` and `entry=funnel_page`. Comparison: same ratio for existing home pages (`entry` is a source category there), same period. A click is a proxy, not a confirmed meeting.
- Minimum sample: 100 funnel-page visitors. Review after 14 days.
- Success threshold: funnel-page rate at least equal to the existing-page rate in the same period.
- Rollback trigger: with at least 100 visitors the rate is below half of the existing-page rate, or zero conversions, or a page error or a content problem is reported.
- Rollback: `git revert -m 1 <merge sha>` of the funnel-pages merge (removes `ladder/`, `ru/ladder/`, `funnel.css`, `ladder-funnel.js`, the build script and the dataLayer bridge in `goals.js`/`ladder.js`). To only stop collecting without removing pages: delete the `ladder-funnel.js` script tag from the pages.

## GA4 finding (checked 2026-11-18 on production, real browser)

Before this change `goals.js` and `ladder.js` sent events only to Yandex Metrika (`ym`). They never touched `gtag` or `dataLayer`. The pages load GA4 (`G-7PL73GGY1E`) only through Google Tag Manager (`GTM-WXMB3PPH`); `window.gtag` does not exist there, and pushing a gtag-style event into `dataLayer` from the page does not reach GA4. So no `cta_*` or `ladder_*` event could ever appear in GA4 for edgeivaikin.com.
Fix in this change (code side): `goals.js`, `ladder.js` and `ladder-funnel.js` now also push `{event: <id>, ...params}` into `dataLayer` (Metrika behaviour is unchanged).
Still needed in the GTM container (needs GTM access, not done): a Custom Event trigger with the regex `^(cta_|ladder_|form_submit|pdf_download)` and one GA4 Event tag (GA4 configuration `G-7PL73GGY1E`) with Event Name = `{{Event}}` and the parameters `entry`, `funnel_step`, `lang`, `ab_hero`, `page`, `source`, `section`, `trigger`, `channel` taken from Data Layer Variables. Then register these as event-scoped custom dimensions in GA4. Until the tag exists the dataLayer events are inert.
